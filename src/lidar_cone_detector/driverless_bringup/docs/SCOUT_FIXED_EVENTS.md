# SCOUT MINI 直线加速与八字绕环落地说明

## 1. 当前实现边界

这是缩比、低速算法验证，不是假设已经拥有大学生方程式赛车。当前底盘输出仍是：

```text
linear.x  = v
angular.z = v * curvature
```

系统不需要 `/odom` 或 `/odometry/filtered` 才能启动。八字圈数使用 IMU 航向增量
和纯雷达门线联合判定；后续队友的建图定位可作为增强输入，但不是当前强依赖。

## 2. 模块关系

```text
LiDAR 锥桶 --------------------> local_path_planner ----> nav_msgs/Path
    |                                  ^
    +--> scout_mission_manager --------+  turn_hint
                |                        　
CH110 IMU ------+--> 圈数状态             speed_limit / stop
                                              |
nav_msgs/Path --------------------> scout_path_controller --> /cmd_vel
```

只有 `scout_path_controller` 可以发布 SCOUT 的 `/cmd_vel`。任务管理器不抢占底盘
控制话题，避免多个节点同时发控制命令。

## 3. 测试场初始尺寸

所有尺寸均为初始建议值，需要根据场地、车宽、雷达检测距离实测确认。

### 3.1 直线加速

- 有效直线：20 m；
- 赛道宽度：2.0 m；
- 普通边界锥间距：2.5 m；
- 起点和终点：各布置一组双排边界门；
- 终点后停车区：至少 8~10 m；
- 第一次闭环速度：0.3 m/s；
- 完成三次无人工接管后再把任务限速提升至 0.8 m/s。

### 3.2 八字绕环

规则几何的 0.5 倍初始版本：

- 两圆心间距：9.125 m；
- 内圆直径：7.625 m；
- 外圆直径：10.625 m；
- 车道宽度：1.5 m；
- 起步直线：7.5 m；
- 退出停车区：至少 10 m。

如果雷达配对受 1.5 m 宽度影响，应优先把 `edge/min_width`、`expected_width` 和
门线宽度参数按实测修改，不要直接放宽所有候选边。当前
`scout_skidpad.launch` 已把规划宽度初始值设为 1.0/1.5/2.4 m。

中心计时位置额外使用双排边界门，以便纯雷达识别。它只用于 SCOUT 算法验证，
不能把它误称为赛事正式计时设施。

## 4. 状态转换

直线：

```text
WAIT_GO
  -> APPROACH_START
  -> ACCELERATING
  -> BRAKING
  -> FINISHED
```

八字：

```text
WAIT_GO
  -> ENTER
  -> RIGHT_LAP_1
  -> RIGHT_LAP_2
  -> TRANSITION_TO_LEFT
  -> LEFT_LAP_1
  -> LEFT_LAP_2
  -> EXIT
  -> BRAKING
  -> FINISHED
```

八字交叉处由状态机改变方向提示，不允许局部规划器仅按最近锥桶自行猜测左右环。

## 5. 上车前检查

1. 硬件急停能够独立切断底盘运动；
2. `/cmd_vel` 只有一个发布者；
3. 锥桶消息 `frame_id=base_link`，或存在到 `base_link` 的有效 TF；
4. 锥桶消息时间戳连续，不使用长期不变的时间戳；
5. CH110 静止时角速度均值稳定，左转 `z>0`、右转 `z<0`；
6. `/mission/stop=true` 时底盘立即停止；
7. 拔掉雷达或 IMU 后能够进入 `FAULT`；
8. 任务未调用 `/mission/start` 前车辆不能运动。

## 6. 分步验收

### 直线

1. 离线 rosbag：起点门、普通边界、终点门都能稳定识别；
2. 顶车架：状态切换时限速和停车话题正确；
3. 0.3 m/s：连续完成 5 次，终点前不误停，终点后 8 m 内停车；
4. 0.5 m/s：连续完成 10 次，无越界；
5. 最后才尝试 0.8 m/s 初始上限。

### 八字

1. 静态转动车体验证 IMU 符号和积分；
2. 手推一圈，确认每个门线只产生一次事件；
3. 0.3 m/s 完成右一圈和右二圈；
4. 单独验证右到左的交叉区切换；
5. 0.3 m/s 完整完成右二圈、左二圈和退出；
6. 连续 5 次无错圈后再提升至 0.5~0.6 m/s。

当前版本使用时间限制退出距离，因为用户明确要求不依赖里程计。它适合低速验证，
但不是精确赛事停车方案。后续有可靠定位或轮速后，应把退出条件升级为门线后的
有符号行驶距离。

## 7. 参考方案取舍

- 采用 Ecurie Aix 公布的感知、定位、规划、控制模块化分层；
- 采用 Bayreuth Elefant Racing 对固定赛项“小团队、简单算法优先”的思路；
- 保留 KIT/KA-RaceIng 的 Delaunay 候选中线和样条结构；
- 采用 TUM 公开架构中任务状态、控制许可和故障停车相互独立的原则；
- 继续使用 AMZ FSSIM 做算法回放和故障场景，但实车接口固定为 `Twist`。

当前没有引入 GraphSLAM、MPC、最小曲率全局优化。对低速 SCOUT 固定赛项而言，
它们会显著增加调试成本，却不能替代门线、状态机、时间戳和停车链路的基础验证。

Bayreuth 的公开方案对 Acceleration 和 Skidpad 使用已知几何中心线，并由定位处理
实际锥桶偏差。等队友的建图定位接口稳定后，建议把这作为版本 B：任务管理器保持
不变，规划器在固定赛项改为“模板中心线 + 位姿配准”，当前纯局部 Delaunay 作为
定位失效时的低速降级路径。现在没有可靠位姿，直接硬编码全局圆弧反而无法落地。
